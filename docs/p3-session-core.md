# Session core (SPO-787)

`Session` in `src/env/session.ts` implements context and the four structured read tools against the merged P3a contract. Construct it on the trusted side with the run configuration, manifest game, phase, cutoff, and `SessionSource`. `corpusSource(corpus, layer, identities)` adapts the verified P1 corpus and P2 layer; `sessionEnvironment(config, source, hooks)` connects it to P4. The harness receives only `SessionTools.call`, never the source, paths, credentials, phase-transition hook, or raw question set.

The constructor copies and freezes run metadata, checks the phase cutoff against the scheduled start or next-morning release, and checks that the run's data-source descriptors exactly match the source's pins. For the corpus adapter, use `source.versions` as the profile descriptors (`source → type`, `manifest_sha256 → manifestSha256`, `release` unchanged), including the transcript index and manifests. P2 manifest and methodology hashes must also match the run. Schedule identity is checked against P1 before returning context or questions.

`visible(envelope, cutoff)` is the shared gate. It implements P3a's three rules, including game release and odds equality, strict publication-time boundaries, and static reference/schedule data. Unknown or malformed availability fails closed. Read tools apply it before joining identities, evaluating coverage, computing totals, or paging. Future and nonexistent game-history/odds requests return the same empty shape. Schedule entries are static inventory and intentionally include future scheduled games; they contain no results.

## Read behavior

- History reads only P1's published tables. Coverage gaps are returned only for eligible games, with the published exclusion reason. Game rows use P1's schedule projection; outcomes remain in the box-score tables. Event order follows `canonical_sequence`; stint order follows `start_sequence`, with deterministic ID tie breaks. Player filters use row membership where present (without a preliminary box-score read for player boxes, player stints or player summaries), event participants for events, and game box-score membership for tables without a player grain (games, team aggregates and possessions). Team filters use row team IDs, or the schedule's teams for matchup tables. A player on an official DNP box row still counts as a game roster member.
- Static player-reference tables reject game, season and time-window filters. They include `age_on_replay_date` when a birth date exists, while retaining the published `age_at_cutoff` field.
- Column definitions come from the release dictionary. The PBP dictionary is an exact copy of `sports-nba-data/docs/data-dictionary.md` at transformation commit `6695e0b18ce83046602f0c016623414af8a95add`; the adapter refuses a different transformation until its dictionary is reviewed. Player-reference definitions are hash-verified from the pinned release. Structured published cells are JSON-encoded strings to satisfy P3a's scalar-cell contract; the event `type` column is exposed as `kind` to avoid the metering proxy's reserved field. Undocumented fields never escape.
- History pages default to 20 rows, maximum 100. Cursors bind to run, game, phase, cutoff, dataset versions and query; totals and offsets refer only to eligible matches. They are opaque pagination tokens, not authorization credentials. Changing the limit/filter requires restarting pagination.
- Injury reads return the latest eligible printed team snapshot per game within the requested report-time window, and player rows from that exact report time. `players_listed` maps to `listed`, `team_absent` to `unknown`, and placeholders to `not_yet_submitted`. An absent team has no carried-forward player rows. Persisted P1 name mappings preserve ambiguous/unresolved IDs as null. `from`/`to` filter printed report times, not schedule times.
- Odds are projected to availability, canonical player, stat, line and P(over). They cover only the requested current or prior game. Settlements are one per distinct offered player/stat/line after release. Official stats and reconstructed participation are used; December 5 uses official box-score minutes when summaries are absent. Missing or ambiguous participation stays `unresolved`, never assumed DNP. No per-book inputs, dispersion or P(under) are returned.
- Questions are exactly P2's complete `agentQuestion` projection. Context uses the budget supplied by P4 and exposes no ledger internals.

## Runner and extension points

P4 implements the public `SessionTools` type, capability-group lookup, snake_case budgets/code results, object code inputs, submission receipts with attempts and clips, and `SessionError` refusals. Validation failures throw with every reported problem and attempts remaining. `LimitError` now subclasses `SessionError`, preserving P4's limit classification and accounting. Identical normalized resubmission returns the persisted receipt, attempt and clips.

Evidence search/fetch is implemented by SPO-788 (see `p3-evidence.md`). Submission validation/released results, workspace operations and the sandbox remain P3d–f. Unsupported tools and absent validation/sandbox hooks fail closed. The core's trusted transition permits only pregame → commit at the same cutoff; P4 constructs a separate postgame Session. This does not implement the later submission validator or sandbox.

## Verification

`test/fixtures/session/corpus.ts` is the reusable adversarial corpus for P3c–f. It plants future records in posts, transcripts, lineups, injuries, odds and PBP, including a future row inside an otherwise eligible game partition. Direct Session tests compare all visible results with and without the planted records, including total counts, columns and page cursors. Runner boundary tests type-check and exercise all 16 tools, covering P4's four special routes and delegation for later tools.

Run `npm run check`, `npm test`, and `npm run format:check`. `npm run session:verify` performs a read-only smoke check against the pinned live corpus using the normal Doppler credentials and verified local cache. It exercises the opener and December 5 in both phases, all history tables, static profiles and the opener's injuries; it makes no model calls or submissions.

## Parsed-data cache

Each `Release` maintains an LRU of verified, deeply frozen parsed rows, keyed by content SHA-256 and decoding format. The defaults are eight objects and 128 MiB of serialized decoded rows per release; this is cache accounting, not a bound on decoder/JavaScript heap usage. Oversized objects remain readable without caching. Concurrent reads of the same content share one load; failed integrity checks or parses are never cached. A cache hit returns the already verified immutable revision, so subsequent changes in external storage cannot alter its contents. Uncached reads still verify the source bytes. Callers that need mutable rows must clone them.

The cache contains trusted raw published rows and is not scoped to a cutoff; every Session read still applies the visibility gate before returning results. PBP internal schedule and coverage lookups reuse their trusted snapshots, while public accessors continue returning defensive copies.

`session:verify` also reports cold/warm parsed-cache timings for Jaylen Brown's 2025–26 player boxes at game 41 postgame, checks that both runs return identical results, and then performs the existing smoke checks. The verified local object cache may already be populated. The review-fix run returned 41 rows in 3.00 seconds cold and 2.03 seconds warm (the reviewed implementation took approximately 260 seconds per query). Deterministic tests separately check read counts, cache bounds/eviction, integrity failures, immutable contents, and the real team-scoped Jaylin Williams injury mapping.
